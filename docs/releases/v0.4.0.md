# rat v0.4.0 release notes

Release scope: Go CLI, embedded Python kernel and the VS Code extension since `v0.3.4`.

This release makes Markdown notebooks first-class: a notebook says what it
needs and rat makes it true, notebooks can build on each other, output
streams as it happens, and every client (a terminal, VS Code, Chattering, an
agent) sees the same kernel and who ran what. It also fixes two ways the
Python kernel differed from IPython that silently broke libraries.

## Highlights

- **Notebooks that describe themselves.** Front matter (`rat.project`,
  `rat.python.requires`, `rat.python.dependencies`) and PEP 723 blocks declare
  a notebook's environment; `rat doctor <notebook>` shows the plan and
  `rat ensure <notebook>` carries it out, installing only what is missing.
  Project detection is ranked (a venv, then a repository or package
  manifest, then weak hints), so every client agrees on a notebook's
  project. Every command takes `--doc <notebook>`.
- **Notebook chains.** `rat.after: [./01-load.md]` declares that other
  notebooks run first, in the same kernel; `rat play` runs the chain once
  per kernel, then the notebook.
- **Live runs.** `rat run` streams output, answers `input()` and password
  prompts, and cancels reliably; `rat play` shows output as it happens.
  `rat events` follows a kernel: every run, its output and who started it.
- **Requirements checked against what is really installed**, from the
  interpreter's own install records.

## Fixed

### Code in a cell can be read back

Cells were compiled as `"<rat>"` with their source kept nowhere, so
`inspect.getsource()` failed on anything defined in a cell, and tracebacks
showed no code lines. Libraries that read a function's source lost it
silently (functai, for one, read no outputs, comments or body from an
`@ai` function defined in a notebook). Each cell is now `"<rat-cell-N>"`,
kept in `linecache` as IPython does.

### Cells run in a real `__main__`

The user's namespace was a plain dict named `__main__`, while
`sys.modules["__main__"]` was the kernel script (or a module IPython made).
Anything that finds a cell's class through its module saw neither:
`pickle` could not pickle an instance of a class defined in a cell, and
libraries resolving the names a class uses found nothing. The namespace is
now a real module installed as `__main__`, as in IPython.

### Also

- Python output streams without `flush=True`.
- Completion without Jedi still answers the name.
- A kernel started by an older rat is reported once by `rat events`
  (restart it to follow it), not retried silently.
- VS Code: a result owns only the images its run made; plots are kept by
  content. Marketplace demo, pi sessions and pirat tools.

## Upgrading

Kernels keep the code they started with: restart a running kernel
(`rat restart py`, or Restart in your editor) to get the fixes above.
